# SEO rules

The site exists to rank on French Kubernetes searches and send readers to Amazon.
Every page must pass `make check`. Strategy and keyword map: `claude/docs/seo.md`.

## Every indexable page

- Exactly **one `<h1>`** containing the page's main keyword; then `h2`/`h3` without
  skipping levels (the checker enforces it).
- **Title** (`:seo_title:`): unique, ≤ 60 characters, main keyword first, brand
  ("The Art of Kubernetes") only if it fits.
- **Meta description** (`:description:`): unique, 120–160 characters, says what the reader
  gets; include "Kubernetes" and a reason to click.
- **Canonical URL**: generated from the content URL, extensionless
  (`https://theartofkubernetes.com/fr/<slug>`). Never hard-code another one.
- **Open Graph image**: 1200×630 for pages (`BOOKS[lang].og_image`), article cover
  (`:logo:`) for articles.
- Language: `lang` metadata on every file; hreflang is automatic for translations
  (same `:slug:`, different `:lang:`).

## URLs

- **Never change a published slug or URL.** Published URLs: `/`, `/fr/articles`,
  `/fr/bienvenue`, `/fr/qu-est-ce-que-kubernetes`, `/fr/operator-or-not-operator`,
  `/fr/multi-cluster-kubernetes`, `/fr/edge-computing-avec-kubernetes`.
- New slugs: short, lowercase, kebab-case, keyword-rich, in the page language.
- Do not re-enable tag, category, author or archive pages (thin content).
- Utility pages (thank-you, legal…) get `:robots: noindex, follow`; they are then left out
  of the sitemap automatically.

## Content and links

- Each article links to at least one other article (`{filename}` links) and to the book
  (`</>` or the landing page sections) in the body text; the template adds the book CTA,
  author box and related articles.
- Descriptive anchor text ("architecture multi-cluster"), never "cliquez ici".
- External links to authoritative sources (kubernetes.io, project sites) are welcome.

## Images

- Descriptive `alt` in the page language for informative images; `alt=""` only for
  decorative images. Always `width` and `height` (no layout shift).
- WebP, kebab-case file names without spaces, generated by `scripts/make_images.py`.
- Below-the-fold images are lazy-loaded (the `responsive_images` filter does it for
  article content); the LCP image (hero cover) uses `fetchpriority="high"`.

## Structured data (JSON-LD)

- Home: `WebSite`, `WebPage`, `Person`, `Book`+`Product` (offer with shipping details),
  `FAQPage`. Articles: `BlogPosting`, `BreadcrumbList`. Article list: `CollectionPage`.
- Structured data must mirror visible content: FAQ entries and price come from the same
  template variables, so edit them there, never in the JSON-LD only.
- Never invent reviews, ratings or an `aggregateRating`. The testimonials are **not**
  marked up as `Review`: Google requires an `aggregateRating` as soon as there are
  several reviews, and we have no real rating to give (Search Console issue of
  2026-11-10, see `claude/docs/seo.md`). Do not add them back.
- Commercial terms in the markup (shipping, return policy) come from `BOOKS[lang]` and
  must be checked on the store's own pages; when unsure, leave the field out.

## Amazon links

- Always use `BOOKS[lang].url` and `BOOKS[lang].link_rel` (via the `buy_button` macro);
  never paste Amazon URLs with tracking parameters (`ref=`, `sr_`…).
- An affiliate tag goes in `AMAZON_ASSOCIATE_TAG`; links then get `rel="sponsored"`.

## Performance (Core Web Vitals)

- No new third-party scripts, fonts or CSS frameworks. Fonts are self-hosted.
- Budget: CSS < 70 KB minified, each image < 200 KB, JS limited to `site.js`.
- Reserve space for anything injected late (e.g. the newsletter form has `min-h-56`).
